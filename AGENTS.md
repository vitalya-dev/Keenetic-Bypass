# AGENTS.md

Генератор списков обхода для роутера **Keenetic**: статические IPv4-маршруты
(`*.bat`) и списки доменов (`*.domains.txt`) для YouTube / Telegram /
Instagram / Facebook. Источник — [iplist.opencck.org](https://iplist.opencck.org/ru/).
Только IPv4. Всё на русском: `README.md` — инструкция для человека,
`AGENTS.md` — контекст для агента. Держи их в согласии.

## Что в папке

| Файл | Что это |
|---|---|
| `update.sh` | единственный генератор: тянет маршруты и домены, чистит, валидирует |
| `youtube.bat` / `telegram.bat` / `instagram.bat` / `facebook.bat` | маршруты (IPv4, формат Keenetic) |
| `youtube.domains.txt` / `telegram.domains.txt` / `instagram.domains.txt` / `facebook.domains.txt` | домены по сервисам |
| `all.domains.txt` | объединение списков доменов всех сервисов без дублей |
| `README.md` | руководство по импорту в веб-интерфейс роутера |

Текущие размеры (сверяйся при правках): маршруты 799 / 138 / 126 / 230,
домены 176 / 20 / 7 / 12, сводный — 212.

## Mental model

- Один сервис → пара файлов: `<svc>.bat` (IP-маршруты) + `<svc>.domains.txt`
  (домены). Плюс производный `all.domains.txt`.
- **`update.sh` — единственный источник истины.** Не скачивать списки руками
  и не редактировать сгенерированные файлы: следующий прогон затрёт правки.
- Скрипт идемпотентен: повторный запуск даёт те же файлы (сортировка + дедуп).
- `update.sh` сам делает `chmod 644` на выходные файлы (иначе `mktemp`
  оставляет `600` и файл неудобно раздавать/читать).

## Команды

```bash
./update.sh        # обновить всё: маршруты + домены, с валидацией
bash -n update.sh  # проверка синтаксиса после правок скрипта
```

Прямые URL (можно грузить без скрипта, `&filesave=1` — отдать файлом):

```
https://iplist.opencck.org/?format=bat&site=youtube.com&data=cidr4
https://iplist.opencck.org/?format=wildcard&site=youtube.com&data=domains
https://iplist.opencck.org/?format=bat&site=facebook.com&data=cidr4
https://iplist.opencck.org/?format=wildcard&site=facebook.com&data=domains
```

сайты: `youtube.com`, `telegram.org`, `instagram.com`, `facebook.com`.

## Правила чистки и валидации (зашиты в update.sh — менять осторожно)

- **Маршруты.** Каждая непустая строка обязана совпадать с
  `^route add <ip> mask <mask> 0\.0\.0\.0$`. Иначе файл не перезаписывается
  (ошибка в stderr, старый файл сохраняется).
- **Домены.** По одному в строке, без `*`. Конвейер: `tr -s` → trim → lower →
  фильтр валидного домена (`^([A-Za-z0-9]([A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)+[A-Za-z]{2,63}$`)
  → выброс `---`-артефактов → выброс непубличных зон
  `\.(google|googlevideo|internal|local|lan|home)$` → длина ≤ 253 →
  `sort -u` → финальный `\n`. Пустой результат = файл не перезаписывать.
- `all.domains.txt` собирается из всех файлов `*.domains.txt` через `sort -u`;
  руками не трогать.

## Импорт в Keenetic

**Статические маршруты (`*.bat`)** — любая прошивка:
Сетевые правила → Маршрутизация → Статические маршруты → «Загрузить из файла»
→ выбрать интерфейс-туннель (напр. `Wireguard0`) → Загрузить. Повторить для
каждого `.bat`.

**Домены (`*.domains.txt`)** — только KeeneticOS 5.0+:
Маршрутизация → «Маршруты по DNS» → раздел «Списки доменных имён» → Создать →
вставить содержимое файла целиком (без `*`) → Сохранить. Затем «Правила
маршрутизации» → Создать → выбрать список + интерфейс → Сохранить. Поддомены
подхватываются автоматически (`youtube.com` накрывает `m.youtube.com` и т.п.).

На прошивках **< 5.0** вкладки «Маршруты по DNS» нет — работают только `.bat`
либо Entware-решения (KVAS, MagiTrickle).

## Диагностика («списки не сработали»)

Порядок проверки:

1. **Сторонний DNS у клиента.** Маршрутизация по DNS работает только через
   DNS-сервер роутера. Если на устройстве прописан `8.8.8.8` или в браузере
   включён DoH/DoT — правило не ловит. Это самая частая причина.
2. **Домен реально в списке** — `grep -i '<домен>' *.domains.txt`.
3. **Маршруты применились** — на роутере в CLI `show ip route` (нужен доступ
   к интерфейсу `Wireguard0`/туннелю).
4. **Туннель поднят** — иначе трафик уходит в никуда. Про сервер и клиентов
   WireGuard см. глобальный скилл `add-wireguard-client`.
5. **Формат `.bat`** — если роутер ругается на файл, пересохранить с CRLF.

## Подводные камни

- **Только IPv4.** Формат `bat` у Keenetic IPv6 не умеет; `cidr4` — осознанный
  выбор.
- Последний `0.0.0.0` в строках `route add` — заглушка шлюза; Keenetic сам
  подставляет выбранный при импорте интерфейс. Руками не править.
- **Перекрытие с Google/Meta.** В YouTube-доменах есть `google.com`,
  `googleapis.com`, `gstatic.com`, в Instagram и Facebook — `facebook.com`,
  `facebook.net`, `fbcdn.*`, `fbsbx.com` и т.п. Соответствующие сети уедут в
  тоннель. Источник для Facebook отдаёт ещё `licdn.com` (это CDN LinkedIn) —
  трафик LinkedIn тоже уедет в тоннель. Если чистить вручную — `update.sh`
  вернёт их при следующем запуске (или правь фильтры в скрипте).
- Секретов в проекте нет и быть не должно. Крупные дампы API (напр. полный
  `iplist.json`) в репозиторий не тащить.

## Обновление списков

Периодически (раз в пару недель) запускать `./update.sh` и заново импортировать
изменённые файлы в роутер. Скрипт валидирует ответ API и **не перезапишет файл
мусором**: пустой или не соответствующий шаблону ответ пропускается с ошибкой.
