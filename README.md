# Маршруты и домены для Keenetic: YouTube / Telegram / Instagram

Данные с [iplist.opencck.org](https://iplist.opencck.org/ru/). В папке два
независимых набора — можно использовать оба сразу или любой один.

## 1. Статические маршруты (IPv4)

Файлы `*.bat`, формат «Routes .bat» — импортируются в веб-интерфейсе
Keenetic. Работает на любой прошивке, тоннель определяется выбранным
при импорте интерфейсом.

| Файл | Сервис | Маршрутов |
|---|---|---|
| `youtube.bat`   | youtube.com   | 799 |
| `telegram.bat`  | telegram.org  | 138 |
| `instagram.bat` | instagram.com | 126 |

1. Веб-интерфейс роутера (`my.keenetic.net` или `192.168.1.1`).
2. **Сетевые правила** → **Маршрутизация** → **Статические маршруты**.
3. **«Загрузить из файла»**.
4. В поле **«Интерфейс»** выбрать туннель, куда должен идти трафик
   (например, `Wireguard0`).
5. Выбрать `.bat`-файл → **«Загрузить»**. Повторить для остальных.

Если импорт ругается на формат — пересохранить файл с CRLF
(Windows-переводы строк) и загрузить снова. Проверка: `show ip route`
в CLI или `Интернет` → `Маршруты`.

## 2. Списки доменов (KeeneticOS 5.0+)

Файлы `*.domains.txt` — голый список доменов, по одному в строке, без `*`.
Это формат вкладки **«Маршруты по DNS»** (DNS-Based Routes).

| Файл | Сервис | Доменов |
|---|---|---|
| `youtube.domains.txt`   | youtube.com   | 176 |
| `telegram.domains.txt`  | telegram.org  | 20 |
| `instagram.domains.txt` | instagram.com | 7 |
| `all.domains.txt`       | все три, без дублей | 203 |

1. **Сетевые правила** → **Маршрутизация** → вкладка **«Маршруты по DNS»**.
2. В разделе **«Списки доменных имён»** → **«Создать»**, задать имя
   (например, `YouTube`).
3. Вставить в поле содержимое файла целиком (по домену в строку, `*` не
   использовать) → **«Сохранить»**.
4. В разделе **«Правила маршрутизации»** → **«Создать»**: выбрать список
   и интерфейс/шлюз (например, `Wireguard0`) → **«Сохранить»**.
5. Повторить для остальных списков.

Поддомены включаются автоматически: `youtube.com` покрывает
`www.youtube.com`, `m.youtube.com` и т.д. — отдельные записи не нужны.

Важно: маршрутизация по DNS работает через DNS-сервер роутера. Если
клиент использует сторонний DNS (8.8.8.8, DoH/DoT в браузере) — правило
не сработает. На прошивках **до 5.0** этой вкладки нет: остаются
статические маршруты из п.1 либо Entware-решения (KVAS, MagiTrickle).

## Обновление списков

Адреса и домены меняются, раз в пару недель перегенерировать и загрузить
заново:

```bash
./update.sh
```

Скрипт скачивает оба набора, чистит и валидирует ответ и **не перезапишет
файл мусором**: маршруты обязаны совпадать с шаблоном
`route add <сеть> mask <маска> 0.0.0.0`, домены — с валидным именем.

## Нюансы

- Только **IPv4**: формат `bat` у Keenetic IPv6 не умеет.
- Последний `0.0.0.0` в строках `route add` — заглушка шлюза, Keenetic
  подставляет выбранный интерфейс при импорте; руками править не нужно.
- В списках YouTube есть общие с Google подсети, а в доменах —
  `google.com`, `googleapis.com`, `gstatic.com`. Точечно это неизбежно:
  часть трафика Google (аккаунт, поиск, Play, рекаптча) уедет в тоннель.
  Если не нужно — удалить эти строки из `youtube.domains.txt` вручную
  после обновления.
- Домены Instagram включают `facebook.com`, `facebook.net` и `fbcdn.*` —
  они уедут в тоннель вместе с Instagram (Meta отдаёт медиа с этих
  хостов). У Telegram лишнего нет: только `t.me`, `telegram.*`,
  `telegra.ph`, `ton.org` и т.п.

```
https://iplist.opencck.org/?format=wildcard&site=telegram.org&data=domains
https://iplist.opencck.org/?format=wildcard&site=instagram.com&data=domains
```

Добавить `&filesave=1`, чтобы сервер отдал файл на скачивание.
